# S01-B04 handover

What the next session needs to continue without reading the log. theserver now computes rankings from the journal, serves API v1 under `/api/v1` with admin tokens and a hand written OpenAPI description, and has its first admin pages under `/admin` (devices, sessions, ranking, settings) with HTMX 4.0.0 embedded. A device can be reset into a new sequence epoch and given a new token while it is connected. `go vet ./...` and `go test ./...` are green on go1.27.1 in ten packages, also under the race detector. In the proof run the ranking matched an independent Python computation exactly, a reset and a token change on live simulators behaved as the protocol says, and a replay of 301 stored events counted nothing twice. With this pass the parts of the season goal exist; what is left is the founder's run of the whole chain on the M150.

## Read this first

- **Rankings are computed, never stored** (D-023). `internal/scoring` walks the hits and misses of a session, or of everything, and is the only package besides the link that reads a payload, and only its `pts` (D-024). Order: points, then hits, both descending, then controller id. Events without a controller are left out.
- **A reset is a new sequence epoch** (D-026, protocol 8.8). `devices.seq_epoch` starts at 1; events carry their epoch; seq, ack and `seq_regression` count within the current epoch. `welcome` carries `ep`. A device whose journal is in another epoch drops its unacknowledged events, starts at seq 1 and connects again at once. A connection stores only into the epoch it read at its handshake.
- **A new token locks the old one out at once** (protocol 8.9). The live connection gets `err unauthorized` and status 1008; events it had sent but the server had not stored are dropped by the server and delivered later with the new token.
- **The status check every 500 ms compares status, token hash and epoch**, so `theserver device reset` beside a running server also takes effect within a second. API and admin page close the connection at once.
- **API v1 needs `Authorization: Bearer <admin token>`** (D-025): none or unknown is 401, revoked is 403. `admin_tokens` keeps revoked rows with `revoked_at`. Only `/api/v1/openapi.yaml` is open.
- **The admin pages call the API in process** (D-027): each page action becomes a request to the `/api/v1` handler as the admin token behind the session cookie. The API itself has no cookie login. The cookie is signed with `<data_dir>/admin.key`, lasts 12 hours, is HttpOnly, Secure, SameSite Strict, path `/admin`. Pages send a CSP without inline script or style and use `http.CrossOriginProtection`.
- **HTMX 4.0.0 is a new major version.** Attribute inheritance is explicit, 4xx and 5xx answers are swapped by default, and the indicator CSS is switched off because the CSP forbids inline style. Guides written for HTMX 1 or 2 are often wrong for it.
- **`docs/openapi.yaml` and `internal/httpapi/openapi.yaml` must stay equal**, and every route must be in both directions; two tests fail otherwise.
- **Where the numbers were measured.** Again `homelab`: Intel Core i9-11900K, 16 logical processors, 128 GB, Windows 11 Pro. Whether this is the M150 is Sascha's to settle.

## Choices made inside the briefing, to confirm

1. **`GET /api/v1/settings`** was added. The settings page needs it, and the concept wants every setting reachable through the API. It is in `openapi.yaml` and D-028.
2. **A reset drops the old epoch's unacknowledged events** on the device and on the server; in the proof that was 11 events of tgt-02. The alternative, renumbering them into the new epoch, would keep those shots but mix two counters. D-026 records the drop; please confirm.
3. **simtarget treats the 1012 close as an ordinary connection end**: a WARN line in its own log and the usual 2 second pause. Only the welcome with the new epoch makes it reconnect at once. Its first hello after a reset therefore still carries the old `last`, and the server logs `replay_expected=118` for a connection that ends 2 ms later.
4. **On a token change the server drops events it received but had not stored**, like on a reset. The device still holds them and delivers them with the new token, which the proof showed with one event.
5. **The ranking without a session** counts every hit and miss, in a session or not.
6. **A session created without an id** gets `s-` and six hex digits. Admin token ids are `adm-` and eight hex digits. `last_used` is written at most once a minute.
7. **`GET /events`** returns payloads base64 encoded as the device sent them, 100 by default and at most 1000, with `offset`.
8. **`admin token revoke` and `device reset`** take the id as an argument or as `--id`; `device revoke` still takes only `--id`, as in B03.
9. **The screenshots used a signed cookie instead of the login form**, so that CC never types a token into a browser field. The token in the dialog screenshot was masked by the helper before the shot.
10. **The CLI commands went into the Task 5 commit**, as the briefing lists them there. The pass has six commits: five tasks and this handover.

## Traps that survived

1. **Backslashes, again.** A Windows path in a Python heredoc turned `\b` into a backspace; the patch script's assertion caught it before anything was written. Write such scripts with the editor tool or use raw strings.
2. **coder/websocket closes the connection when a Read context expires.** The replay helper reads with a timeout, so the server logged its end as `read failed ... EOF`, not as a close with status 1000.
3. **Headless Edge leaves processes behind.** The Edge launcher hands over and exits, so `taskkill /T` misses the browser. The helper gives every run its own profile directory and stops exactly the processes whose command line contains it.
4. **Two rows with the same `created_at`** sorted differently between runs; the admin token test now advances its clock between adds.
5. **HTMX `hx-confirm` uses `window.confirm`**, which blocks a headless browser; the helper answers the dialogs over the DevTools protocol.
6. **The briefing arrived as `docs/briefings/briefing-S01-B04.md`** and was moved to `docs/briefings/S01-B04.md` byte for byte (SHA-256 5c8ec38f...60c4).

## Not done, open

- **The page can show a device online for a moment after a reset or token change.** `Disconnect` closes in the background and `Online` lists the connection until the close finishes; `devices-reset-message.png` shows tgt-02 online in epoch 2 with the old last ack 107 until the next refresh. A fix is to mark the connection as closing before `Disconnect` returns and leave it out of `Online`.
- **simtarget could treat status 1012 as expected** and reconnect at once without a WARN line (choice 3).
- **No admin token management on the page**, only on the command line; no passkeys and no roles (S02).
- **`events.kind` still has no index.** The query plan (checked with Python's SQLite 3.45 on the proof database) shows the session ranking searching the session and controller index and sorting in a temporary tree, and the ranking over everything scanning the whole table. At 801 events that is instant; with a large journal it has to be measured, and the ranking has no need for the sort by `ts_server`.
- **No paging on the admin pages** and no way to stop following the ranking.
- **Fingerprint pinning** is still missing in simtarget, and no firmware has talked to the link yet.
- **`docs/concept.md` section 3** still names Go 1.26; the concept is the author's.
- **The session `proof` is still running** in the proof data; it is throwaway.
- **Writes outside the repository folder**: the build cache and the temporary directories of the tests. No new modules; HTMX was downloaded once, as approved, into `dist/htmx`.
