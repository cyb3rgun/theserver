# S01-B06 handover

What the next session needs to continue without reading the log. theserver has its settings foundation: one registry in `internal/settings` describes all 14 settings with kind, default, unit, range or values, restart flag and label, description and why in English and German (D-030). The admin interface speaks English and German from catalogues of 171 keys each (D-031). The configuration file is written back from the registry, and the log level, the link timings and the two admin settings take effect at once (D-032). Every change is logged (D-033). `/admin/settings` is an editable form with help as structure (D-034), backed by `GET` and `PUT /api/v1/settings` and `POST /api/v1/settings/reset`. `docs/settings.md` is generated by `theserver settings doc`. `go vet ./...` and `go test ./...` are green on go1.27.1 in twelve packages with 190 test functions. The scenario editor stands on this and is the next pass; `docs/scenario.md` lies beside it, untouched and not committed.

---

## Read this first

- **A setting is added in one place.** Declare it in `internal/settings/registry.go` with both texts, add the field with matching toml tags to `config.Config`, and run `go run ./cmd/theserver settings doc --out docs/settings.md`. Tests fail otherwise: a missing text in either language, a field without an entry or an entry without a field, different defaults, a stale reference.
- **Durations are whole numbers of their unit.** `store.busy_timeout_ms` holds 5000, not a duration; text such as `2s` is accepted and converted when it is a whole number of the unit. The file keeps its numbers.
- **Live or restart is a property of the setting.** Live: `log.level`, the five `link.*` timings, `admin.language`, `admin.session_hours`. Restart: `server.listen_addr`, `server.data_dir`, `tls.cert_file`, `tls.key_file`, `store.busy_timeout_ms`, `log.format`. `config.Runtime` applies live values through `OnChange`; `serve` connects that to a `slog.LevelVar`, `link.Server.SetConfig` and the admin options.
- **Changes need the file the server was started with.** Without `--config`, `PUT` answers 409 `no_config_file` and the page disables saving. A setting that an environment variable or a flag sets is refused with the field code `overridden` and shown locked, since the file would not win at the next start.
- **The file is regenerated, not edited.** `config.Write` writes the whole file from the registry; comments written by hand are lost, tables that are not theserver sections are kept with their values. Unknown keys inside a theserver section are still an error when loading.
- **Only the winning value of an override is checked**, as before B06: an empty `THESERVER_SERVER_DATADIR` does not matter when `--data-dir` is given.
- **Typed errors all the way.** `settings.ValueError` carries a code; the API returns one `FieldError` per refused setting in `error.fields` with code, range, unit or allowed values; the page translates the code. The certificate pair is checked only after every single value passed.
- **Language.** Cookie `theserver_lang`, else `admin.language`, else English. The switch sits in the header of every page, the login included, and lasts as long as a login; logout clears it. Templates are parsed once per language with a bound `t` function; `word` translates values such as a device status.
- **html/template reads `data-on...` as a script handler.** An attribute whose name after `data-` starts with `on` is escaped as JavaScript. The counter uses `data-singular` and `data-plural` for that reason.
- **Machine.** The proof ran on `homelab`: Intel Core i9-11900K, 16 logical processors, 128 GB, Windows 11 Pro.

## Choices made inside the briefing, to confirm

1. **Ranges.** Every number got a closed range, most of them new: busy timeout 0 to 600000 ms, ack interval 1 to 10000 ms, ack batch 1 to 1024, ping interval 1 to 3600 s, ping answer time and greeting time 1 to 600 s, login duration 1 to 720 h.
2. **Live or restart**, as listed above. The link timings apply from the next batch, ping or connection; the certificate is not reloaded live.
3. **Settings set by an environment variable or flag are refused**, not written to the file, and locked on the page.
4. **Without a configuration file changes are refused** (409), instead of the server creating a file somewhere.
5. **Tables of the file that are not theserver sections are accepted and kept**, which the write back needs; unknown keys in our sections stay errors; comments written by hand are not kept.
6. **"Writes the session cookie" was read as a cookie per admin session**: the language lives in its own cookie with the lifetime of a login, not inside the signed session cookie.
7. **German addresses the operator formally** ("Sie"). The language names in the switch are translated (English page: German; German page: Deutsch, Englisch).
8. **The pages show a translated text per API error code** instead of the English message of the API, which goes to the debug log. For a refused session start that means "This is not possible in the current state." without the details.
9. **The settings page is a plain form** with post, redirect and get, not HTMX; the unsaved count is a small script of our own with a subresource integrity hash.
10. **`GET /api/v1/settings?lang=` with an unsupported language answers 400**; an empty one means English.
11. **The certificate pair is checked after the single values**, so a page may first show a range error and only on the next save the pair.
12. **`docs/openapi.yaml` changed in the API commit**, since the coverage tests demand it there; `config.Describe` is gone.
13. **The season log was not extended** with B06; it records B01 to B05 as its pass asked.

## Traps that survived

1. **Python heredocs still eat backslashes**, twice in this pass, both caught by the patch assertions before anything was written. Patch scripts go through the editor tool.
2. **Checking every override layer broke the command tests**, which neutralise the environment with empty variables and then pass `--data-dir`; only the winning value is checked again.
3. **`data-one` became a JavaScript string** in html/template; see above.
4. **A server started through Git Bash ignores CTRL_C_EVENT**; start test servers directly from Python.
