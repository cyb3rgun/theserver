## Read this first

- **"Online" now means "not leaving".** `link.Server.Disconnect`, the status watcher, the shutdown and a failed write mark a connection as leaving before they close it in the background. `Online` leaves such a connection out, and `SendCommand` answers `ErrDeviceOffline` for it, even while its close handshake still runs. A new connection of the same device registers as before.
- **The token answer carries the table.** `POST /admin/devices/{id}/token` returns the dialog and, in an `<hx-partial hx-target="#devices" hx-swap="outerHTML">`, the devices table with a notice. HTMX 4 swaps the dialog first and the partial after it.
- **The index is not the one the briefing named.** The briefing asked for `events (kind)` and `events (kind, controller_id)`; measured, they made both rankings slower, and the architect agreed to `events (session_id, kind)` instead (D-029). `EachEvent` no longer sorts; `ListEvents` still returns the order of arrival. Anything that needs order must use `ListEvents`.
- **`TestRankingQueryPlans` pins the plans.** A session ranking must search `events_session_kind` with both columns and sort nothing; the ranking over everything scans. A new index can change the plan without a failing ranking test, and this test is what notices.
- **The briefing file is the correction message.** No original S01-B05 was on disk; `docs/briefings/S01-B05.md` holds the message word for word under a header that names the two answers given during the pass.
- **The season log follows THESITE's season 2 log**, because the game track has none; the architect chose that format.
- **Machine.** Every number of this pass comes from `homelab`: Intel Core i9-11900K, 16 logical processors, 128 GB, Windows 11 Pro.

## What was proven

**The status fix.** `TestDisconnectedDeviceIsOfflineAtOnce` (link) connects a device, calls `Disconnect` for each of the three reasons while the client reads nothing, and checks `Online` and `SendCommand` at once; afterwards the client reads the expected close status. `TestDeviceIsOfflineAtOnceAfterResetAndNewToken` (admin) does the same through the page with a live link: after the reset the row says offline, epoch 2, last ack none; after the new token the answer holds the dialog, the partial, the notice and an offline row. Both tests were red against the old code (Online without the flag, SendCommand without the check), and the admin test was red without the partial. A headless Edge run with two simtargets showed the same on the real page: offline right after the reset, then online again in epoch 2 once simtarget reconnected; dialog open and the row offline right after the new token, the partial used up, one table on the page; no WARN or ERROR in the server log.

**The index.** `dist/rankbench` filled a journal with 270,000 events in 30 sessions (3 devices, 3,000 events each per session, about 35 percent hits and 15 percent misses) and timed `scoring.Ranking`, median of five:

| Variant | Session ranking | Ranking over everything |
| --- | --- | --- |
| B04 build, B04 indexes | 22 ms | 538 ms |
| briefed: `(kind)`, `(kind, controller_id)` | 118 ms | 715 ms |
| only `(session_id, kind)` | 19 ms | 576 ms |
| briefed plus `(session_id, kind)` | 17 ms | 722 ms |
| briefed plus ANALYZE | 26 ms | 696 ms |
| B05 build, B04 indexes | 19 ms | 415 ms |
| B05 build, migration 0004 | 14 ms | 431 ms |

The first five rows ran on the B04 walk, which still sorted. Without the sort, reading all 93,854 hits took 184 ms instead of 257 ms. The query plans of B05, SQLite 3.53.4 inside modernc.org/sqlite v1.59.0:

```
session hits:   SEARCH events USING INDEX events_session_kind (session_id=? AND kind=?)
session misses: SEARCH events USING INDEX events_session_kind (session_id=? AND kind=?)
all hits:       SCAN events
all misses:     SCAN events
```

Before 0004 the session queries used `events_session_controller (session_id=?)` and every plan ended in `USE TEMP B-TREE FOR ORDER BY`. The plan test was red without the migration and red with the sort put back.

**The migration on real data.** A copy of `dist/proof4/data` from the B04 proof opened with schema version 4 and all 801 events. The B05 server on it answered both rankings, session proof and everything, exactly as the B04 server did, whose answer the independent Python check had confirmed.

## Choices made inside the briefing, to confirm

1. **The fix sits in the link, not only on the page.** The page shows what the API reports, and the API asks `Online`; fixing `Online` makes the API, the page and commands agree. The commit is still `fix(admin)`, as briefed.
2. **`EachEvent` itself stopped sorting**, instead of a second, unsorted variant next to it. The question in the pass spoke of a variant; with the ranking as the only caller outside a counting test, a sorted `EachEvent` would have been unused.
3. **D-029 records the index decision.** The briefing asked for D-001 to D-028 in the log; the log lists D-029 as well, marked B05.
4. **`seasons.md` and the README** gained the B05 line, the log link and version 0.5.0-dev in the build lines; the correction did not list them.
5. **The perf commit's message was corrected once** before the push: it first said the founder had decided, where the answer came from the session like every earlier "agreed with the architect". Its hash changed from 7ab1300 to c62132e; nothing had been pushed.

## Traps that survived

1. **Backslashes in heredocs, twice more.** A JSON script written through a bash heredoc lost the doubled backslash of `\\s`, and a Python heredoc with a Windows path turned `\b` into a backspace. Scripts with backslashes go through the editor tool.
2. **Git Bash resolves a missing name to its `.exe`.** `rm -rf dist/rankbench` removed `dist/rankbench.exe`. Keep data directories and binaries under different names.
3. **The planner has no statistics.** theserver never runs ANALYZE, so SQLite picks among indexes by shape alone; an index on a column with few values, such as `kind`, can win against a much better one. Measure before adding an index, and let the plan test catch the change.
4. **A test that checks a query builder by its parameter proves little.** The first plan test called `eventQuery` with `false` itself and would have stayed green if `EachEvent` sorted; the tests now call `walkQuery` and `pageQuery`, which the methods use.
