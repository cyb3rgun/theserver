# S01-B14 handover

What the next session needs to continue without reading the log. The admin has a look that can be changed in one file. `internal/admin/static/tokens.css` holds every colour as a custom property, in a light and a dark set; no stylesheet, page or script carries a colour of its own, and a test greps every static file of ours and fails on one that does (D-072). Three themes are chosen in the header beside the language: auto follows the browser and the system, light and dark are the manual choices, the cookie `theserver_theme` keeps the choice, and the page carries it as `data-theme` before the body starts, so a dark screen never flashes white (D-073). The mark of thesite sits top left and is the favicon (D-074). Both sets hold every text at 4.5 to 1 against its surface, which a test computes (D-075). `go vet ./...` and `go test ./...` are green on go1.27.1 in 17 packages with 461 test functions.

---

## Read this first

- **One file, three blocks.** The light set stands on `:root, :root[data-theme="light"]`, the dark one under `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` and again under `:root[data-theme="dark"]`. The two dark blocks are the same values, which a test enforces; a new token goes into all three.
- **The grep test is the fence.** `TestEveryColourIsAToken` reads every `.css` and `.js` of `internal/admin/static` except `tokens.css` and the vendored `htmx.min.js`, and fails on a hex colour, an `rgb(` or an `hsl(`. A colour that has to exist belongs in the token file with a name that says what it paints.
- **The canvas reads the tokens.** `editor.js` and `preview.js` hold a small `paint(name)` that asks `getComputedStyle(document.documentElement)` for a custom property; they call it while drawing, so a theme change reaches the canvas at the next frame without a reload.
- **The theme is on the html element, not in a script.** No inline script guesses the theme; the server writes `data-theme` because it read the cookie. Auto is the absence of a choice, and then `prefers-color-scheme` decides in CSS alone.
- **The favicon is the one file with a colour beside the tokens.** A browser loads it without our stylesheet, so it carries the colours of thesite; the mark inside the page is the same two paths drawn from `--mark-ground` and `--mark-accent`.
- **The mark came from thesite as a file**, `src/assets/logo.svg`, commit `96d7d56` of 11 September 2026, byte for byte. It was not redrawn; D-074 records where it came from.
- **`docs/look.md` is the founder's page.** It names every token, what it paints, and the three steps to change the look.

## What was proven

`go test ./...` is green. The tests that carry this pass:

- `TestEveryColourIsAToken`: every static file of ours is read line by line; a colour outside `tokens.css` fails with the file, the line and the value. It also checks that the token file holds the names the pages rely on and both dark blocks.
- `TestBothThemesAreReadable`: eighteen pairs, three blocks, WCAG ratio computed from the parsed values; the lowest pair in the light set is the muted text on the raised panel, the lowest in the dark set is the accent on the panel, both above 4.5. It also compares the automatic dark set with the chosen one, value by value.
- `TestThemeSwitchAndCookie`: the page without a cookie is auto, the switch sets the cookie with the same flags as the language cookie, the choice survives a reload on three pages and on the login page, an unknown value reads as auto, the mark is in the header and the favicon answers.
- `TestEveryPageInEveryLanguage` and `TestLanguageSwitchChangesTheLabels` now expect `data-theme` on the html element, which is how a missing theme would be caught.
- `dist/proof12` shoots the devices page, a room, the editor and the settings page in light and in dark, and two pages in German, from a real server.

## Traps that survived

- **A new page needs nothing, a new colour needs three edits.** Adding a token means adding it to the light block and to both dark blocks; a value that differs between the two dark blocks fails the test rather than surprising somebody at night.
- **`--muted` is the tightest pair.** It sits close to 4.5 on the raised panel; a lighter grey there fails the test, which is the point.
- **The canvas asks the page for its colours at draw time.** A canvas drawn once and never again keeps the colours of the theme it was drawn in; everything in the editor redraws, so this has no effect today.
- **The theme cookie is HttpOnly**, so a proof script sets it through the switch of the page, as `dist/proof12/script.json` does.
- **The devices table still shows the room as the text a device reported**, not as its room; the device page and the room page show the room. It is a leftover of B13 and is noted below.
