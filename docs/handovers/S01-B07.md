# S01-B07 handover

What the next session needs to continue without reading the log. theserver has scenario packages. `docs/scenario.md` is committed, and `internal/scenario` implements it: the manifest, reading a directory or a zip, 28 validation codes plus `version_taken` from the server, each with an English and a German text, and the manifest hash (D-035, D-040). Every version lives in `content/<id>/<version>/package.zip` as uploaded, indexed in SQLite; a published version never changes (D-036, D-037). Targets report what they hold in `health`, are told with `content_available`, download with their device token over HTTPS, and report `content` events (D-038, protocol section 8.10). A session plays one published version, checked against the age its devices are set for (D-039). The admin has a catalogue with upload and check, a page per scenario, the assignment on the sessions page and a page per device. The whole chain runs end to end with simtarget in the tests and in the proof run. A server without `--config` creates `theserver.toml` in its data directory with the first saved change, and every translated error shows the API detail below it. `go vet ./...` and `go test ./...` are green on go1.27.1 in 14 packages with 232 test functions. ## Read this first

- **One package decides what a valid scenario is.** `internal/scenario` depends on nothing of the server. `Load(dir)`, `LoadZip(path)` and `ReadZip` return a `Package` with the manifest and the SHA-256 of every file; `Validate(m, files)` returns `[]Problem{Field, Code, Detail}` in a stable order; `Hash(m)` is the manifest hash. A package that cannot be read at all is a `*LoadError` with `bad_package`, `no_manifest` or `bad_manifest`.
- **The manifest lists every file.** `[files]` maps each path of the package except `manifest.toml` and `SIGNATURE` to its SHA-256 in lower case hex (agreed with the architect). A named file that is not listed or not present is `missing_media`, a wrong hash `hash_mismatch`, a file of the package that is not listed `unlisted_file`.
- **The manifest carries the version** (agreed). Above the latest published: a draft, replacing a draft of the same version. At or below: refused with `version_taken`. "Put, publish, put again gives version two" therefore needs version 2 in the second manifest.
- **Shapes are points** (agreed): polygon three or more, rect two opposite corners, circle one centre and `radius`; keyframes carry the same fields; every point lies on the canvas. `age_rating` is one of 0, 6, 12, 16, 18 (agreed). INTERACTIVE states are the table `[media.state]` (agreed; the example in the document is not TOML).
- **Fixtures are written by a test.** `internal/scenario/testdata/valid/{video,interactive}` are hand made; `testdata/invalid/<code>` and `bad_package.zip` are what `TestBrokenFixtures` writes from them; change a breakage and run `go test ./internal/scenario -update`. Media placeholders are marked `-text` in `.gitattributes`, so their hashes survive a checkout. `scenariotest` hands them to the tests of other packages. The hash of the INTERACTIVE fixture is pinned: a change of the canonical form changes every package hash.
- **Nothing published changes.** `internal/content` writes an upload below `content/.incoming`, validates it and renames it into place; a replaced draft comes back if the index refuses the new row. A package that cannot be stored is answered 422 `invalid_package` with its problems; a stored draft keeps its problems in the index and cannot be published (`has_problems`).
- **`device_scenarios.current` means held now** (agreed): a row stays once a device held a version; `current` follows the latest report, `installed_at` is when it last became current. A `health` without `scn` says nothing; an empty `scn` says nothing is held.
- **Announcements go out in three places** (agreed): at assignment, when a device joins a session, and after the first `health` with holdings on a new connection of a device that was offline. The link sends them in parallel; offline devices are answered `waiting`.
- **The age check** (agreed): `devices.min_age`, 18 by default, set with `theserver device add --min-age`, `POST /api/v1/devices/{id}/min_age` or the device page. Assignment only while the session is created. The check runs on assignment, on joining and on lowering an age, each in one transaction.
- **Downloads** are `GET /api/v1/scenarios/{id}/{version}/package.zip`: an approved device with its token gets published versions, an admin every version; `Range` works through `http.ServeContent`; `X-Manifest-SHA256` is the manifest hash, the same `sha` that `content_available` names.
- **Settings.** `content.max_upload_mb` (2048, 1 to 65536, live) and `content.dir` (empty means `content` in the data directory, restart). `docs/settings.md` is regenerated.
- **Without `--config`** every command reads `theserver.toml` in the data directory that defaults, environment and flags give, and the runtime creates it with the first saved change, logging `msg="configuration file created"`. A file that appears there after the start is not overwritten: 409 `conflict` until a restart. D-032 notes the change.
- **Machine.** The proof ran on `homelab`: Intel Core i9-11900K, 16 logical processors, 128 GB, Windows 11 Pro.

## Choices made inside the briefing, to confirm

1. **Validation rules the document leaves open** (D-035): ids are 1 to 64 lower case letters, digits, hyphens and underscores for every id; `orientation` is portrait or landscape, `fit` cover, contain or fill; an unknown key is `unknown_field`; `[rules]` and at least one appearance are required (`missing_section`); `duration_s` and `required_hits` are at least 1 and every time lies within the duration; the title needs both languages, a given description or zone name too; keyframes and appearance media states only in INTERACTIVE and LAYERED; no follow up in VIDEO; at most one follow up per appearance and zone class; a LAYERED appearance names a state found in any layer, since v1 does not name the layer.
2. **Codes beyond the list of the briefing:** `bad_package`, `no_manifest`, `bad_manifest`, `unknown_field`, `missing_section`, `bad_id`, `duplicate_id`, `bad_version`, `bad_tier`, `missing_text`, `bad_age_rating`, `bad_value`, `zone_shared`, `appearance_without_zones`, `unknown_appearance`, `unknown_media_state`, `not_in_tier`, `unlisted_file`, `version_taken`.
3. **A zip holds the package at its root or in one top directory;** unsafe, repeated or irregular names are `bad_package`. `cover.png` is optional; a package without one shows a neutral placeholder.
4. **The manifest hash** is the SHA-256 of the canonical JSON of the manifest behind the domain string `cyb3rgun scenario manifest v1`; it is what `sha` and `X-Manifest-SHA256` carry, not the SHA-256 of the zip.
5. **The index has two columns more than the briefing lists:** `published_at` and `problems`. `uploaded_by` is the name of the admin token.
6. **Upload answers:** 201 for a new draft, 200 for a replaced one, 422 `invalid_package` when nothing is stored, 413 `too_large`. `content.max_upload_mb` ranges from 1 to 65536 and is live; `content.dir` needs a restart.
7. **Protocol details:** `sha` is text; a `failed` report carries the optional reason `e`; the device answers `content_available` with `ok` true also for a version it holds or installs; the link applies the reports of every stored batch, duplicates included, and writes a health list again only when it changed.
8. **simtarget** sends a `health` right after connecting, keeps packages in `--content-dir` (default `content` in its journal directory), resumes a cut download up to three times, and takes the whole package again from a server that ignores `Range`.
9. **Routes beyond the briefing:** `GET /api/v1/scenarios/{id}/{version}/cover.png` for the catalogue, and the agreed `POST /api/v1/devices/{id}/min_age`. The device page is `/admin/devices/{id}/view`.
10. **The sessions page** offers the latest published version of each scenario; the API accepts any published version. The create form no longer takes a scenario as text; the API still accepts it as a label until a version is assigned.
11. **Task 0:** the file is looked up in the data directory that the defaults, the environment and the flags give; it may name another data directory, which then holds the data while the file stays where it was found. A file that appears after the start is refused with 409 `conflict`. The error detail is shown for every translated API error, the token dialog included.
12. **docs/openapi.yaml parses as YAML again:** four existing descriptions with a comma were cut off inside their flow mappings; they are quoted now. No test checks the YAML itself; it was parsed with PyYAML during the pass.

## Traps that survived

1. **Heredocs still eat backslashes and quotes.** Twice a long heredoc failed on quoting and once a `\n` became a newline before it reached Python; patch scripts go through the editor tool, and the patch helper refuses anything that does not match exactly once.
2. **`O_APPEND` on Windows forbids `Truncate`**, see above.
3. **CBOR `omitzero` keeps an empty list and drops a nil one**; that is what tells "holds nothing" from "says nothing".
4. **slog quotes values with `=`**, so the log has `range="bytes=100-"`.
5. **The announcements of one assignment go out side by side**, and a download can start before the answer of its announcement is logged; the chain test checks only the order that is fixed.
6. **The `waitfor` step of the proof tool does not wait for promises**; the proof polls inside an `eval` instead.
7. **The file control of the upload form shows the browser's own words**, German on this machine, whatever the page language.
