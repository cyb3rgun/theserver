# S01-B08 handover

What the next session needs to continue without reading the log. theserver has a scenario editor. A person opens a draft on `/admin/scenarios`, empty or as a copy of a published version, and builds the scenario at `/admin/editor/<draft id>`: upload a clip, draw zones on the paused frame, move them through time with keyframes, put appearances on the timeline, set reactions and rules in a property panel where every field carries its help in both languages, play it with the mouse as the pistol, check it, publish it. Drafts live on the server with their media (D-041); the server writes the manifest, computes the `[files]` hashes, zips the package and publishes it through the chain of B07 (D-042); the editor is one vendored script with its integrity hash (D-043); the preview runs the rules of `docs/scenario.md` section 7 in JavaScript and compares them with the same rules in Go (D-044); media is taken as it is uploaded, with the container and the codec read from the header (D-045); the fields come from one registry (D-046); and `docs/openapi.yaml` is parsed in a test (D-047). `go vet ./...` and `go test ./...` are green on go1.27.1 in 16 packages with 260 test functions. The whole way, from an empty draft to a version installed on a simulated target, ran in the browser in both languages.

---

## Read this first

- **A draft is a row, not a document in the browser.** `scenario_drafts` (migration 0007) holds the manifest as JSON and what the server knows about every media file; the files live under `content/drafts/<draft id>/media/`. Ids look like `d-3f2a1c9b7e01`, which is a valid scenario id, so the directory name is always safe.
- **The manifest of a draft carries no `[files]` table and no version.** The server writes both when it publishes: `scenario.WriteManifest` writes `manifest.toml`, every media file is hashed into `[files]`, the zip goes through `content.Put` and `content.Publish` like an upload. A test compares a package from the editor with the fixture it was copied from, down to the files table and the hash.
- **A change is a JSON merge patch** (RFC 7386) on the manifest, `PATCH /api/v1/drafts/{id}`. The merged document must decode into `scenario.Manifest` with unknown fields refused, else nothing is stored and the field is named (`bad_manifest`, 400). What is stored is what the model writes back, so nothing the model does not know survives a change. The answer carries the whole draft and, in `touched`, the problems that lie in the parts the change named.
- **The version is decided at publish**: one above the latest published version of that scenario. The draft stays afterwards and works towards the next one; `scenario_drafts.published_version` says what it last published.
- **Media is checked at upload, never converted** (D-045): `internal/mediakind` reads the boxes of an MP4 up to the sample description, the elements of a WebM up to the track entry, the first page of an Ogg stream and the signature of a PNG. A clip is MP4 with H.264 or AV1, an overlay WebM with VP8, VP9 or AV1, a sound Ogg with Vorbis or Opus, a cover PNG; anything else is 415 `bad_media`. The duration and the picture size come from the browser in a second call, `PATCH /api/v1/drafts/{id}/media/{name}`, and the editor takes the duration and the canvas of the scenario from the first clip.
- **The property panel is generated.** `internal/editor` lists every field with its place in the manifest, its control, its limits and its texts in both languages. A test walks every key against `scenario.Manifest` by reflection, so the registry cannot drift from the model; another fails when a text is missing. The settings page and the editor render the help with the same template, `{{template "help" .}}`.
- **The rules live twice** (D-044): `internal/scenario/rules.go` and `internal/admin/static/rules.js`. Both write the same trace for the same shots. Two scripted runs on the INTERACTIVE fixture are recorded in `internal/scenario/testdata/rules/interactive.json`; a Go test compares the engine against the file, and the browser proof compares the JavaScript engine against the same file and against the server. The Go engine is the seed for theclient.
- **What section 7 left open is settled** (agreed with the architect): `timeout_counts_as_hit` turns timeout costs on for the whole scenario, `on_timeout` says per appearance whether this one costs (`penalty`), costs nothing (`nothing`) or ends the run (`end`); a follow up with `then = end` leaves the figure on its last picture, `back:<state>` plays that state, `next` moves the window of the next appearance that has not started to now; the score never falls below zero, `score_cap` above zero holds it; a miss costs points, never a life; the last life lost ends the run; a shot meets the first live zone in manifest order.
- **The scripts hold no text.** `editor.js`, `rules.js` and `preview.js` read every word from data attributes of the page, so both languages come from the catalogues. A test compares the integrity hash in the page with the hash of the file that is served. When a script swaps a fragment into the page it calls `htmx.process`, else the forms inside it would leave the page on submit.
- **Everything goes through API v1.** The editor page never touches the store: `editorPatch`, `editorField`, `editorUpload` and the rest call `/api/v1/drafts/...` in process. A test walks the rendered page for the address of every draft endpoint and calls each one.

## The commands

```
theserver serve --data-dir <dir>              # as before
```

The editor adds no command. Everything is in the browser:

- `/admin/scenarios` opens a draft (empty, or "Edit as a new version" on a published version) and lists the drafts in flight.
- `/admin/editor/<draft id>` is the editor, `/admin/editor/<draft id>/preview` the preview.
- `POST /api/v1/drafts`, `GET /api/v1/drafts`, `GET|PATCH|DELETE /api/v1/drafts/{id}`, `POST /api/v1/drafts/{id}/media`, `GET|PATCH|DELETE /api/v1/drafts/{id}/media/{name}`, `POST /api/v1/drafts/{id}/validate`, `POST /api/v1/drafts/{id}/trace`, `POST /api/v1/drafts/{id}/publish`.

## What was proven

The proof ran on the homelab (i9-11900K, 16 logical CPUs, 128 GB, Windows 11) with the binary of this pass, in headless Edge over DevTools, `dist/proof8`:

- A draft was opened from the catalogue form, the browser recorded a six second H.264 MP4 of a figure walking and uploaded it through the media panel; the server read `mp4 h264` from the header, the browser measured it, and the editor took `duration_s = 8` and the canvas `540x960` from it.
- Two zones were drawn with synthetic pointer events, the first with keyframes at 0 and 2000 ms, and given a name in both languages, a class and a value; two appearances were put on the timeline with the keyboard (`a`), the first with its zone and its media state.
- The check named the two open problems in English and in German, each linked to the object; after the second appearance got its zone the check was clean and the publish button opened.
- Publishing wrote version 1 of `range-proof` (204 KB, manifest hash `4e67d354...`), it appeared in the catalogue, it was assigned to a session, announced to `tgt-01`, downloaded and reported installed. Nothing in this run touched a file by hand.
- The preview played the draft in both languages, counted points, hits and misses, and its check answered "The rules of the browser and of the server agree on this run."
- The trace comparison on the INTERACTIVE fixture, both recorded runs: `browser_equals_recorded: true`, `browser_equals_server: true`, 12 events each, score 100 and 150.
- 21 screenshots in `dist/proof8/shots`, the server log without a single WARN or ERROR.

## Choices made inside the briefing, to confirm

- The draft stays after a publish and works towards the next version; deleting it is a button on the editor page.
- The second call of an upload is `PATCH /api/v1/drafts/{id}/media/{name}` with `duration_ms`, `width` and `height`; the briefing named the call but not its address.
- `GET /api/v1/drafts/{id}/media/{name}` was added, because a video element has to load the file; it needs an admin token like every other draft endpoint.
- `POST /api/v1/drafts/{id}/trace` was added so that the preview can compare the two engines where a person can see it.
- A draft is opened for the tiers video and interactive only; another tier is refused at creation with a sentence that says so.
- A new draft starts at age rating 18, licence `private`, the admin of the session as author, canvas 1080x1920 portrait, and the rules of the example in `docs/scenario.md`.
- The editor takes the duration and the canvas from the first clip that is measured, and in a video scenario makes it the main video.
- "This frame as cover" captures the picture on the screen as `cover.png`, so a scenario made in the editor has a cover in the catalogue.
- A zone drawn in the editor starts without a name, so that an optional text is not half filled; the check would otherwise ask for the other language.
- A change while a zone has keyframes writes a keyframe at the playhead. Without keyframes it changes the zone itself.

## Traps that survived

- **The integrity hash in the page is HTML escaped.** `html/template` writes a `+` of the base64 as `&#43;`; a browser reads the attribute back before it checks the hash, so this is correct, but a test that compares the raw base64 fails. `TestEditorScriptIntegrity` compares the escaped form and says why.
- **HTMX only knows what it processed.** A fragment put into the page with `innerHTML` keeps its forms outside HTMX, and the next submit leaves the page. `editor.js` calls `htmx.process` after every swap; the proof found this the hard way.
- **A synthetic pointer cannot be captured.** `setPointerCapture` throws for a pointer that is not really down, which a test or a proof sends; the canvas guards both calls.
- **Zones move only in the interactive and layered tiers.** The editor lets a keyframe be set in a video scenario and the check then names `not_in_tier`; the button does not know the tier yet.
- **The check panel is a snapshot.** It is filled by the check button and by the first render of the page; after a change it says "The draft changed since this check." The publish button follows the draft itself, not the panel.
- **A published version keeps the media names of its draft.** `media/<name>` comes from the file name the browser sent, made safe; two uploads with the same name replace each other.

## Not done, open

- LAYERED and REALTIME are validated but not drawn. The editor page works in video and interactive.
- There is no undo. Every change is saved at once; a wrong change is corrected by the next one.
- The blood overlay is played in the preview but not composited in the editor canvas, and the impact sound plays only in the preview.
- Two people editing the same draft at the same time overwrite each other; a draft carries no version of its own for that.
- The Go rule engine is not yet the engine of a session: nothing replays a journal through it. That is where theclient and the coaching pass will meet it.
- The trace is compared for the fixture and for the shots of a preview run; a fuzz over random shots would be a cheap next step.
- `docs/concept.md` still names Go 1.26; the season log ends at B05.
