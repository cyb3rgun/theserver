# S01-B10 handover

What the next session needs to continue without reading the log. The device journal is a database. `pkg/journal` keeps its events in `journal.db` in the directory it is given, in WAL mode with foreign keys on and `synchronous` FULL: an append is one transaction and returns when the event is on the card, an ack deletes the rows up to the acked sequence, and a power cut cannot take back a hit a target handed out (D-052). The calls a caller makes did not change, apart from the `Close` a database needs; `Open` takes options, `WithSync` and `WithDeviceID` (D-053). A `journal.cbor` of an earlier version is imported once and renamed, so a device updated from `v0.1.0` keeps what it held. The durability is tested, not assumed (D-054), and the close of the pass is tagged `v0.2.0` (D-055). `go vet ./...` and `go test ./...` are green on go1.27.1 in 17 packages with 273 test functions.

---

## Read this first

- **One file, one connection.** `journal.db` lives beside the content directory of a simulated target; the pool is one connection, because one device writes one journal. The pragmas are on the connection string, as they are in `internal/store`: `busy_timeout`, `journal_mode(WAL)`, `synchronous(FULL)`, `foreign_keys(ON)`.
- **What is in memory mirrors the database.** The pending events are read at open and kept in a slice, so `After` and `Pending` answer without a query; every change writes first and updates the slice after. The database is the truth, the slice is the copy.
- **`synchronous` is FULL by default** (agreed with the architect): NORMAL in WAL mode survives a killed process but may roll the last transactions back after a power cut, and a power cut is the reason this pass exists. `WithSync(journal.SyncNormal)` is there for a simulator that cares more about speed than about a card. What it costs, measured on the homelab (i9-11900K, NVMe): 10,000 appends in 24.0 s with FULL, 2.402 ms each, against 1.06 s with NORMAL, 0.106 ms each.
- **The API stands.** `Open`, `Append`, `Acked`, `After`, `Epoch`, `Reset`, `LastSeq`, `Pending` keep their signatures; `Close`, `DeviceID` and `Path` are new, and `Open` is variadic, so every call written before this pass still compiles. A closed journal refuses `Append`, `Acked` and `Reset` with `journal.ErrClosed`; the readers keep answering from memory.
- **`WithDeviceID` is a guard, not decoration.** The first open writes the id into `meta`; a later open with another id is refused by name. Two devices pointed at one directory used to mix their sequences silently.
- **An old journal is imported, never ignored.** `journal.cbor` is read on the first open of a directory that has no `journal.db`, written into the database with its epoch, its last sequence and its unacknowledged events, and renamed to `journal.cbor.imported`. A file that cannot be read fails the open instead of starting empty.
- **An open database cannot be removed on Windows.** That is the whole change outside `pkg/journal`: `cmd/simtarget` and the tests that hand a journal to the simulator close it. Nothing in `internal/simtarget` knew the file format.

## What was proven

`go test ./...` is green, and `go test -race ./pkg/journal ./internal/simtarget` is green. The tests that carry this pass:

- `TestJournalKeepsEventsWithoutAClose`: 40 appends, the handle dropped without a close and without a checkpoint, as a killed process drops it; another journal opens the same files and finds all 40 with their ids and payloads.
- `TestJournalSurvivesACopiedWalFile`: 25 appends and an ack, then `journal.db`, `journal.db-wal` and `journal.db-shm` copied away while the journal is open, which is the image a power cut leaves; the copy opens with the right count, the right last sequence and the 20 unacknowledged events in order.
- `TestJournalImportsTheCborFile`: a CBOR journal of epoch 3 with three pending events is imported, renamed, continued at sequence 10, and a second open imports nothing again.
- `TestJournalRefusesWhatItCannotRead`, `TestJournalDeviceID`, `TestJournalRefusesChangesAfterClose`, and the restart, epoch and replay tests that were there before.
- `TestRunKeepsItsJournalAcrossARestart` in `internal/simtarget`: the simulator runs, stops, two events are written into the journal with nothing connected, and the second run replays exactly those two, carries the sequence on and leaves the server with every event once in one unbroken sequence.
- `TestJournalAppendTiming`: reported, never asserted. The default is 1,000 appends so the suite stays quick; the briefing's 10,000 is `-appends=10000`.

## Where things are

- `pkg/journal/journal.go`: the whole package, schema included.
- `pkg/journal/journal_test.go`: the durability tests and the timing.

## Traps that survived

- **A test that opens a journal must close it.** On Windows `t.TempDir()` cleanup fails on an open database file, and the failure reads as an unrelated cleanup error. `t.Cleanup(func() { j.Close() })` at every open.
- **`synchronous=FULL` is 25 times slower per append than NORMAL** on this machine. It is still 2.4 ms, which a target that journals a shot every hundred milliseconds does not feel, but a load test that appends as fast as it can will.
- **The import runs only when there is no `journal.db`.** A directory that holds both keeps the database and leaves the CBOR file alone; that is deliberate, and the file is not renamed in that case.
- **An event id is a 16 byte blob.** It is stored as bytes, not as text; a reader that expects a string will find none.

## Not done, open

- No fsync test can be written in Go alone: the copied write ahead log is the closest an in process test comes to a power cut. A real proof needs a machine that loses power, which is a bench test, not a unit test.
- The journal never shrinks its file: SQLite reuses the pages of acked events, but `journal.db` keeps its high water mark. A target that runs for a season may want `VACUUM` in a later pass.
- `meta` holds the acked sequence, and nothing reads it yet; it is there for a device that wants to report what it has without walking the events.
- Everything the B09 handover left open stays open: LAYERED and REALTIME are not drawn, the lock is per admin token, undo lives in the page that made the changes, the blood overlay is composited only in the preview, nothing replays a journal through the Go rule engine, and no fuzz runs over the trace.
