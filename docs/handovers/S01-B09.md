## Read this first

- **`pkg/` is public, `internal/` is not** (D-048). `pkg/protocol` is the device link envelope, its message types and the codec. `pkg/scenario` is the manifest model, the loader, the validation and the rule engine of section 7, with `pkg/scenario/scenariotest` for the fixtures. `pkg/journal` is the device side journal: sequence, epoch, the events the server has not acknowledged, replay after a dropped connection. Nothing else may be imported from outside, and a pass that changes anything under `pkg/` bumps the tag (D-049).
- **The journal is its own package now.** `simtarget.OpenJournal` is `journal.Open`, `simtarget.Draft` is `journal.Draft`, and the file name constant is `journal.FileName`. `simtarget` builds on it; the three journal tests moved with it and hand in plain drafts instead of using the generator, which lives on the other side of the import.
- **A draft is locked while somebody edits it** (D-050). The row carries `locked_by`, the id of the admin token, `locked_name`, the name that token had, and `locked_at`, the last refresh. Opening the editor takes the lock, the page refreshes every minute, and it releases on leave. A lock lives five minutes after its last refresh, so a closed browser frees the draft by itself.
- **The lock refuses changes, not reads.** `POST` and `DELETE /api/v1/drafts/{id}/lock` and every endpoint that changes a draft, its media, its history or its publish answer 409 `draft_locked` while somebody else holds it. Reading and the check stay open, so a second person can look and check without taking anything away.
- **A release carries the stamp of the lock it releases.** `DELETE /api/v1/drafts/{id}/lock?at=<locked_at>` empties the lock only while it still carries that stamp. Without this, a navigation inside the editor released the lock the new page had just taken, because the old page leaves after the new one has loaded and both are the same token. The proof found it; the story is in the commit `a page that leaves does not release a newer lock of its own`.
- **There are two ways back from a change** (D-051). In the browser: the last fifty manifest states, undo and redo on the two buttons in the bar and on Ctrl and Z and Ctrl and Shift and Z. On the server: `scenario_draft_history`, the last twenty changes of a draft with the manifest as it stood before each one, listed by `GET /api/v1/drafts/{id}/history` and written back by `POST /api/v1/drafts/{id}/history/{version}/restore`. The state before a restore becomes the newest version, so a restore can itself be undone.
- **Undo does not send the manifest as it stands.** A JSON merge patch keeps every key the target no longer has, so `editor.js` builds the patch that turns one state into the other, with a null for every key that went away. The function is `diff` and it is twenty lines.
- **The page reaches its own script through `HX-Trigger`.** The swap events of HTMX do not arrive at a listener on the body of this page; the proof measured it. Everything the server changes behind a fragment says so with `HX-Trigger: draft-changed`, or `draft-restored` for a restore, and `editor.js` reads the draft again on those. A new fragment that changes the manifest has to set one of the two headers, or the canvas will keep drawing the state before it.
- **The keyframe control knows the tier.** Zones move in `interactive` and `layered` only. In `video` the two buttons are not on the page, a line under the picture says why, the keyboard list drops the two keys, and `editor.js` refuses the K key and any keyframe a drag would write. The validator is untouched: a keyframe patched into a video draft is still `not_in_tier`.

## The commands

```
theserver serve --data-dir <dir>              # as before
```

Nothing new on the command line. In the browser:

- `/admin/editor/<draft id>` takes the lock when it opens and shows the notice when somebody else holds it.
- `POST /admin/editor/<id>/lock` refreshes it, with `take_over=1` it takes it over; `POST /admin/editor/<id>/unlock?at=<stamp>` releases it.
- `GET /admin/editor/<id>/history` is the version list, `POST /admin/editor/<id>/history/<version>/restore` writes one back.
- API v1 gained `POST|DELETE /drafts/{id}/lock`, `GET /drafts/{id}/history` and `POST /drafts/{id}/history/{version}/restore`, all in `docs/openapi.yaml`.

## What was proven

The proof ran on the homelab (i9-11900K, 16 logical CPUs, 128 GB, Windows 11) with the binary of this pass, in headless Edge over DevTools, `dist/proof9`. Three browsers, two admin tokens, one server:

- Browser A, as mausi, opened an INTERACTIVE draft, drew two zones and held it. Its page showed no lock notice.
- Browser B, as sascha, opened the same draft while A was still on it, and saw "mausi is editing this draft. Nothing you change here is saved." in English and the same sentence in German, each with the take over button.
- B took the draft over after the confirmation. The log carries one line: `draft lock taken over draft=... from=mausi to=sascha`. B then deleted a zone in the property panel.
- A, still open, refreshed its lock a hundred seconds after it had loaded, was answered 409, and its page said "The lock on this draft is gone. Reload the page to see who holds it."
- Browser C drew two zones on a draft of its own, deleted one in the property panel, pressed Ctrl and Z and the zone came back, pressed Ctrl and Shift and Z and it went again, then restored the newest version from the history panel and the zone came back a second time, this time from the server.
- The VIDEO draft carried no keyframe button at all and the hint in its place, in both languages: the browser counted `{"buttons":0,"hint":true}`.
- 11 screenshots in `dist/proof9/shots`, the server log without a single WARN or ERROR.

The proof found four defects, all fixed in this pass and all with a test: the lock answer left the manifest out and the property panel then listed no zone; a change in the panel never reached the undo stack; `drawTimeline` threw on a zone that had just been deleted; and the release of a leaving page took away the lock of a newer page of the same person.

## Traps that survived

- **HTMX swap events do not reach this page.** `htmx:afterSwap` and `htmx:beforeSwap` on `document.body` never fired for a swap into `#history`, measured in the browser. `HX-Trigger` does. Anything new that changes the manifest behind a fragment must send the header.
- **A release without its stamp is a weapon.** `DELETE /drafts/{id}/lock` without `at` releases unconditionally for that token. The page always sends the stamp; a caller that does not will hand the draft to whoever asks next.
- **The undo stack is per page, the history is per draft.** A reload empties the stack; the version list survives it. A restore clears the stack on purpose, because the way back from a restore is the newest entry of the history.
- **`DraftLockTTL` and the refresh belong together.** The page refreshes every `TTLMs / 3`, which is a hundred seconds for the five minute lock; two refreshes may be lost before anybody else can walk in. Changing one without the other makes a lock that either dies while somebody works or holds a draft that nobody is on.
- **A change that moves nothing writes no version.** The editor sends a patch on every drag; a history of identical states would push the interesting ones out.
- **The panel undo hangs on the submit event.** `editor.js` remembers the state before a panel change when the form goes. A future control that changes the manifest without submitting a form in `#panel` has to call `remember` itself.

## Not done, open

- LAYERED and REALTIME are still validated but not drawn, and the editor page works in video and interactive.
- The lock is advisory across tabs of the same person: a second tab of the same admin takes the lock from the first without a word, because the identity is the admin token and not the page.
- Undo and redo live only in the page that made the changes. Another browser sees the version list, not the stack.
- The blood overlay is played in the preview but not composited in the editor canvas, and the impact sound plays only in the preview.
- The Go rule engine is still not the engine of a session: nothing replays a journal through it. That is where theclient meets it.
- The trace is compared for the fixture and for the shots of a preview run; a fuzz over random shots would still be a cheap next step.
- `docs/concept.md` and `docs/usb-protocol.md` carry uncommitted changes of the architect in the working tree; this pass did not touch them.
