# S01-B03 handover

What the next session needs to continue without reading the log. theserver is reachable: HTTPS with a self signed certificate on first start, the device link of `docs/protocol.md` with handshake, replay, commands and keepalive, device tokens from the command line, and a second binary, `simtarget`, that behaves like a target. `go vet ./...` and `go test ./...` are green on go1.27.1 in eight packages. The proof run of this pass stored exactly what the simulators sent: 302 of 302 events across five deliberate drops, and 15,064 of 15,064 from fifty devices at about 250 events per second, without an error or warning line in the server log. For the season goal only the ranking API and the first admin page are missing (B04).

---

## Read this first

- **The link contract is section 8 of `docs/protocol.md`.** It states what `internal/link` does, down to the close codes. Change the code and that section together.
- **A device needs `device add` before it can connect.** The server finds the device through the SHA-256 of its bearer token (unique index, migration 0002), requires status approved, and then requires the hello to name that device. `device add` prints the token once; there is no way to show it again and no rotation yet.
- **Batches, acks and replay.** Events are stored every 100 ms or 32 events and every batch is acknowledged with the contiguous seq. A reused seq or a moved event id gets `bad_message` naming the seq, the batch is dropped and the connection closed; the device replays it and keeps failing until the operator resets it, which the admin UI does not offer yet.
- **Newest connection wins.** A second connection of a device closes the first without handshake after the first has stored what it received.
- **Sessions are attributed by device time** (D-021): an event belongs to the session of its device whose start and end cover its `ts`. That is only as good as the device clock, which `time_mark` is meant to keep close.
- **The store serializes writes of the process.** Many connections wait on a mutex instead of backing off in the SQLite busy handler. A `device` command beside the running server still meets the busy timeout, which is enough.
- **Where the numbers were measured.** The machine is `homelab`, an Intel Core i9-11900K with 16 logical processors and 128 GB, Windows 11. Whether this is the M150 of the season goal is not known to CC. The S01-B02 handover calls its 10,000 event figure a measurement "on the M150"; that was written without checking and refers to this same machine.

## Choices made inside the briefing, to confirm

1. When a hello leaves nothing to replay, an `ack` with the welcome seq follows immediately, because the protocol asks for an ack when the replay completes.
2. `TouchLastSeen` runs on every received frame, as briefed. At 250 events per second it cost nothing visible.
3. The store changes the link needs (token lookup, migration 0002, `ConflictError`, write serialization) went into the `feat(store): session api` commit, since they belong to the store module.
4. An unknown event kind is stored like any other. A class in the hello that differs from the registered one is logged, an unknown class is refused.
5. `--rate` counts shots and their outcomes; the health report every 30 seconds comes on top, so 60 seconds at rate 5 give 302 events.
6. simtarget answers `set_config` with `ok:false`, because the briefing lists only `time_mark`, the session commands and `reboot` as accepted. It stops on a refused token instead of retrying. Its journal lives in `data/simtarget/<id>` and is not fsynced.
7. `device add` refuses an id that exists; it does not rotate tokens.
8. The revocation check runs every 500 ms and the command timeout is 5 seconds; neither is in the configuration, since the briefing did not list them.
9. The HTTP server writes its own complaints, such as a plain HTTP request on the HTTPS port, at WARN, not ERROR.
10. A hello timeout closes the connection without an `err`; the briefing says close, and a device that sent nothing may not be listening.

## Traps that survived

1. **Backslash escapes still bite.** A `\n` inside a Go string written through a Python heredoc arrived as a real newline twice in this pass. `gofmt -l` caught both. Build such lines with `chr(92)` or write the file with the editor tool.
2. **`go mod tidy` drops a required module that nothing imports yet.** It removed `coder/websocket` between the dependency commit and the link commit. It was required again with `go get github.com/coder/websocket@v1.8.15`, the version resolved in task 1, not with a fresh `@latest`.
3. **coder/websocket closes the whole connection when a Read or Write context expires**, and `Close` waits up to 5 seconds for the close frame of the peer. A test client has to keep reading while the server closes, or the close takes 5 seconds.
4. **fxamacker/cbor pads or cuts a byte string into a Go byte array.** That is why `protocol.EventID` has its own decoder that insists on 16 bytes.
5. **Python on Windows does not see the `/tmp` of Git Bash.** Keep scratch files that both use under `dist/`.
6. **Ctrl+C from the agent shell** still needs `SetConsoleCtrlHandler(NULL, FALSE)` in the parent and a console of its own; the proof driver does both.
7. **Briefings arrive under other names** (`docs/briefing-S01-B02.md`, `docs/briefings/briefing-S01-B03.md`). They were moved to `docs/briefings/<pass>.md` byte for byte.
