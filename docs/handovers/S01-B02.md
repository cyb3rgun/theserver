# S01-B02 handover

What the next session needs to continue without reading the log. theserver has its memory: SQLite in the data directory, a versioned schema, a device registry and an idempotent event journal. `go vet ./...` and `go test ./...` are green on go1.27.1, `internal/store` holds twenty six test functions, and an append of 10,000 events in one transaction took 169 ms on the M150, about 59,000 events per second. No network link yet; that is B03 and it reads `docs/protocol.md`.

## Read this first

- **The journal is the contract, not the SQL.** `AppendEvents(ctx, deviceID, events)` writes one batch in one transaction. An event id that is already stored counts as a duplicate and is never written twice, which is what replay after a dropped connection produces. A sequence number that another event holds is `ErrSeqConflict`, an event id stored under another device or sequence number is `ErrEventConflict`, and either rolls the whole batch back. `AckSeq` and `LastSeq` are the highest sequence number with no gap below it, so a journal that starts at 2 acknowledges nothing until 1 arrives.
- **A device row must exist before its events.** `events.device_id` is a foreign key and foreign keys are on, so the link layer registers the device (UpsertDevice) before it appends. `sessions` and `session_devices` exist in the schema but have no Go API yet.
- **`controller_id` is filled by the caller** (D-012, settled with the architect during this pass). The store keeps the payload as received and decodes nothing, so this pass takes no CBOR dependency. B03 fills the field when it decodes the `ev` frame.
- **Open the database only through `store.Open`.** The pragmas of D-011 ride in the DSN, so SQLite applies them to every connection of the pool. A second `sql.Open` somewhere else would run without WAL and without foreign keys.
- **Every timestamp is unix milliseconds in UTC** (D-014). `ts_server` and every `created_at` come from the store clock, which `store.WithClock` replaces in tests; `ts_device` is what the device sent.
- **Tokens are only ever stored hashed** (D-015). `HashToken` is SHA-256, `VerifyToken` compares in constant time. Issuing tokens is B04.

## Choices made inside the briefing, to confirm

1. `store.Open(ctx, dataDir, opts ...Option)` keeps the signature of task 2 while task 5 passes the configured busy timeout, through `WithBusyTimeout`; `WithClock` is what makes the tests deterministic.
2. The insert says `ON CONFLICT(event_id) DO NOTHING` instead of `INSERT OR IGNORE`. It is the same idempotency on the event id, but it ignores only that conflict; `OR IGNORE` would also swallow a CHECK or NOT NULL violation.
3. `UpsertDevice` never moves `status` or `created_at`, and a nil token hash keeps the stored token. Status moves only through `SetStatus`, so a device that reconnects cannot talk itself back to pending.
4. `ListEvents` filters on `ts_server`, orders by `ts_server, device_id, seq` and returns at most `DefaultListLimit`, 100, when the filter names no limit.
5. `AppendEvents` checks before it touches the database: a non empty event id, a sequence number of 1 or more, a kind, and a payload that is not nil. An empty payload is allowed.
6. `VerifyToken` on an unknown device returns `ErrDeviceNotFound`, not a plain false, so the caller decides what to tell the device.
7. `/healthz` sets `"status":"error"` as well as `"db":"error"` when it answers 503.
8. The README was updated with the store setting, the `--db-info` flag and the database in the health answer. The briefing did not list it; a README that describes flags it does not have is worse than the small step outside the task list.

## Traps that survived

1. **Writing Go through a bash heredoc mangles backslash escapes.** `\n` and `\t` inside a Go string arrived as a real newline or tab and broke the file twice. Write Go files with the editor tool, or from Python with `chr(92)`, and let `gofmt -l` and `go vet` catch what slips through.
2. **Ctrl+C from the agent shell needs help** (carried over from B01). Processes started there inherit "ignore Ctrl+C"; the parent has to call `SetConsoleCtrlHandler(NULL, FALSE)` before starting the server for a CTRL_C_EVENT to arrive.
3. **A unique violation does not kill the transaction.** SQLite rolls back only the failing statement, which is why the journal can ask who holds that sequence number before it rolls the batch back deliberately. Code that changes this path has to keep that order: insert, ask, classify, roll back.
4. **`go mod tidy` pulls the test only modules of sqlite into `go.sum`**, about 30 lines that no build needs. That is normal for a module with a large test suite; `go.mod` lists nine indirect modules.

## Not done, open

- **No API for `sessions` and `session_devices`.** The tables exist and events reference them, but a session row can only be written with raw SQL today, which is what the filter test does. B03 or B04 needs `CreateSession`, `SetSessionState` and the device assignment.
- **No CBOR decision yet.** Payloads are stored as received. B03 has to decide the library with `go get @latest` and record it before it can read `ev` frames.
- **The 503 path of `/healthz` has no automated test.** The briefed layout has no test file for `cmd/theserver`, so only the 200 path was proven by hand.
- **`events.kind` has no index.** A filter on kind alone scans the table. It matters from the first ranking query, not before.
- **Nothing prunes the journal.** Events are immutable and never deleted in S01, so the file grows with every shot; retention is a later decision.
- **`docs/seasons.md` still lists only S01-B01** under S01 in progress, with D-001 to D-006. The B02 line and D-009 to D-015 are not in it; the briefing did not ask for it.
- **Writes outside the repository folder**, needed by `go get`, `go build` and `go test`: the module cache (`C:\Users\sash710\go\pkg\mod`, now with modernc.org/sqlite and its nine indirect modules), the build cache and the temporary directories of `go test`.
