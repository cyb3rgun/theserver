# Briefing S01-B03: the device link and the simulated target

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, `main` at `52efbbe`. Implementer: CC. Architect: Mausi.

This pass makes theserver reachable: WebSocket over TLS, CBOR messages as in `docs/protocol.md`, the handshake with replay, and a second binary `simtarget` that behaves like a target so the whole path can be tested without firmware. After this pass, the season goal is missing only the ranking API and the first admin page (B04).

## 1. Decisions taken in this briefing, with reasons

- **CBOR via `github.com/fxamacker/cbor/v2`.** Pure Go, RFC 8949, deterministic encoding, the de facto standard in Go; the same library family exists for ESP-IDF (tinycbor) so the wire format stays boring. D-016.
- **WebSocket via `github.com/coder/websocket`.** Pure Go, context aware, maintained; supports `net/http` handlers directly. D-017.
- **TLS from the first start.** On startup, if `data/tls/server.crt` and `server.key` do not exist, theserver generates a self signed certificate (ECDSA P-256, 10 years, SANs `localhost`, `127.0.0.1`, the hostname) with the standard library and logs its SHA-256 fingerprint. Operators install a real certificate by replacing the two files. Devices in S01 verify the fingerprint (pinning) or skip verification with an explicit flag; the simulator does the latter. D-018.
- **Device tokens issued from the command line in S01.** `theserver device add --id tgt-01 --kind target --class esp` prints a token once, stores only the hash, sets status `approved`. Admin UI issuance is B04 or later. D-019.
- **Handlers leave `main`.** New package `internal/httpapi` owns the router, `/healthz`, and the `/link/v1` upgrade; `cmd/theserver` only wires config, store, TLS and lifecycle. This also makes the 503 path testable, which CC flagged. D-020.
- **Sessions get a Go API now** (`CreateSession`, `StartSession`, `StopSession`, `AddSessionDevice`, `GetSession`, `ListSessions`), closing the gap CC flagged, so `welcome` can carry the active session id. D-021.
- **Subcommands.** `theserver` gains a small subcommand layer: `serve` (default when no subcommand is given, so existing usage keeps working), `device add|list|revoke`, `db info` (replaces `--db-info`, keep the flag as a deprecated alias for this season). D-022.

### Task 5: device link server

`internal/link`: one goroutine per connection.

- Upgrade at `/link/v1`; `Authorization: Bearer <token>` checked against `store.VerifyToken`; on failure send `err unauthorized` as an HTTP 401 before upgrade.
- After upgrade expect `hello` within 5 seconds, else close. Validate `proto == 1`, else `err proto_unsupported`. Look up `LastSeq`; if `hello.last < LastSeq` send `err seq_regression` and close. Reply `welcome` with `ack`, `now`, and the id of a running session that contains the device, or null.
- Read loop: `ev` frames appended through `store.AppendEvents` in batches (flush every 100 ms or 32 events, whichever first), `ack` sent with the contiguous seq after every flush; `ErrSeqConflict` and `ErrEventConflict` produce `err bad_message` with the conflicting seq in the message and close the connection, they never crash the server. `res` frames are matched to pending commands by id.
- Write side: a per connection outbound queue; `SendCommand(deviceID, name, args) (Result, error)` with a 5 second timeout; a registry `Online() []DeviceStatus` of connected devices with connect time, last event time and last ack.
- Keepalive: WebSocket ping every 15 seconds, pong timeout 10 seconds, then close and mark offline. `TouchLastSeen` on every received frame.
- Structured logs: connect, hello, replay count, disconnect with reason.

Tests with `httptest.NewTLSServer` and a minimal client written against `internal/protocol`: unauthorized token gets 401; hello then two events get an ack of 2; reconnect with `last=2` after the server stored 2 replays nothing and acks 2; reconnect with `last=1` while the server has 2 gets `seq_regression`; a client that resends events 1..3 after a drop where the server stored only 1..2 results in exactly one new row; a conflicting seq closes the connection with `bad_message`; `SendCommand` receives the `res`; ping timeout marks the device offline.

Commit: `feat(link): websocket device link with handshake, replay and commands`.

### Task 7: the simulated target

`cmd/simtarget`, its own binary, flags: `--server wss://127.0.0.1:8443`, `--id`, `--token`, `--insecure` (skip TLS verification, prints a warning), `--rate` events per second (default 5), `--controllers` how many controller ids to rotate (default 3), `--journal <dir>` for its own persisted sequence counter and unsent events, `--drop-every <seconds>` to close the connection deliberately and reconnect after 2 seconds (0 disables), `--duration <seconds>` (0 runs until Ctrl+C).

Behaviour: on start, load the journal, connect, `hello` with the last journaled seq, replay everything above `welcome.ack`, then generate events: for each shot a `shot` event, then with 70 percent probability a `hit` with random normalized x, y, a zone drawn from head, torso, arm, leg, and points 100, 50, 25, 25 respectively, else a `miss`. Events are journaled locally before sending and removed after the server acks them. `health` every 30 seconds. Answers `time_mark` and `session_*` commands with `ok`, `reboot` with `ok` followed by a reconnect, unknown commands with `ok:false`.

Tests: the journal survives a restart (write, restart, replay contains the unacked events); the event generator produces valid protocol frames.

Commit: `feat(simtarget): simulated target for link testing`.

### Task 9: proof and handover

Fresh data directory. Then:

```
dist\theserver.exe device add --id tgt-01 --kind target --class esp
dist\theserver.exe serve --config data\theserver.toml
```

In a second console, with the printed token:

```
dist\simtarget.exe --server wss://127.0.0.1:8443 --id tgt-01 --token <token> --insecure --rate 5 --drop-every 10 --duration 60
```

Expect: connects, replay 0, events flow, every 10 seconds a deliberate drop, reconnect, replay of whatever was unacked, and at the end `dist\theserver.exe db info` shows an events count equal to the simulator's own sent count (print both; they must match exactly, no duplicates, no gaps). Then a load run: 50 simulators (a small PowerShell loop is fine) at 5 events per second for 60 seconds; report events per second stored, CPU and memory of theserver at the end, and any error log line. `device revoke tgt-01` while connected must close the simulator's connection within one second.

Then `docs/handovers/S01-B03.md`, commit `docs(handover): add S01-B03 handover`, push.
