# Briefing S01-B14: light and dark, and the mark in the corner

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, `main` at the B13 handover or later. Implementer: CC. Architect: Mausi. Look and wording belong to the founder; this pass builds the mechanism and a restrained default that he can change in one file.

## 1. Decisions

- **Every colour becomes a token.** One file holds the design tokens as CSS custom properties: surfaces, text, borders, accent, and the status colours for online, offline, warning and error. Two sets, light and dark. No component, page or inline style carries a colour of its own any more; a test greps the stylesheets and fails on a hard coded colour outside the token file. The founder changes the whole look by editing that one file. D-072.
- **Three theme settings, like the language.** Auto follows the browser and the operating system, light and dark are the manual choices; the switch sits in the header next to the language switch, the choice lives in a cookie for the session, and the default is auto. The page renders with the theme already applied, without a bright flash on a dark screen. D-073.
- **The mark goes top left**, as an SVG copied from thesite into the admin assets, linking to the overview. The admin version is the restrained one: flat, no glow, one colour from the tokens, the accent only where thesite puts it. The same file gives the favicon. D-074.
- **Both themes are readable**, text against its surface at a contrast ratio of at least 4.5 to 1, status colours never carrying meaning by colour alone; every status keeps its word next to the dot. D-075.

## 2. Tasks

1. `feat(admin)`: the token file per D-072 with the light and dark sets, all existing pages moved onto the tokens, the grep test.
2. `feat(admin)`: the theme switch per D-073, cookie, auto detection, no flash, texts in `en` and `de`.
3. `feat(admin)`: header with the mark per D-074, favicon, the mark file taken from thesite and recorded with its source in the decision.
4. `docs`: D-072 to D-075, a short `docs/look.md` naming the tokens and what each one paints, so the founder knows which line to edit; README, seasons, briefing verbatim; handover; push.

## 3. Acceptance

Every page renders in light and dark, in both languages, without a colour outside the token file; the switch survives a reload; auto follows the system setting; the mark and the favicon are in place; the contrast requirement holds on the settings page, the device list and the editor.

`git log --oneline origin/main`, screenshots of devices, rooms, editor and settings in light and dark, the token list from `docs/look.md`, and anything odd. A gap is a question, never a substitution.
