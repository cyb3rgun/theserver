# Briefing S01-B02: storage, migrations and the event journal

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, local `C:\Projects\CYB3RGUN\THESERVER`, branch `main` at `7c1d35d`. Implementer: CC. Architect: Mausi.

This pass gives theserver its memory: SQLite, versioned migrations, devices and the idempotent event journal. No network link yet; that is B03 and uses `docs/protocol.md`, which Sascha places in `docs/` before this pass.

## 1. Decisions taken in this briefing, with reasons

- **`modernc.org/sqlite`**, pure Go, no cgo, no C toolchain on Windows or the Raspberry, one binary stays one binary. Version via `go get @latest`, recorded as D-009.
- **Own migration runner, no library.** Numbered SQL files embedded with `embed`, applied in a transaction each, recorded in `schema_migrations`. Twenty lines of Go, no dependency, no surprises. D-010.
- **WAL journal mode, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`** set on every connection. WAL gives concurrent readers during writes, which the admin UI will need. D-011.
- **Events are immutable.** Insert only, never update, never delete in S01. Idempotency by primary key on `event_id` and a unique index on `(device_id, seq)`. D-012.
- **Event ids are UUIDs stored as 16 byte BLOBs**, generated on the device; the store never invents one. Go side uses the standard library `crypto/rand` with RFC 9562 version 4 layout, no uuid dependency. D-013.
- **Timestamps as integer unix milliseconds** everywhere, UTC, no SQLite datetime strings. D-014.
- **Device tokens for S01 authentication**, stored as SHA-256 hashes, mTLS in S02. D-015. This pass only creates the column and the hashing helper; issuing tokens is B04 (admin).

## 3. Schema, migration 0001

```sql
CREATE TABLE schema_migrations (
  version    INTEGER PRIMARY KEY,
  applied_at INTEGER NOT NULL
);

CREATE TABLE devices (
  id               TEXT PRIMARY KEY,
  kind             TEXT NOT NULL CHECK (kind IN ('target','controller','bridge')),
  class            TEXT NOT NULL DEFAULT 'esp' CHECK (class IN ('esp','pi','pc')),
  name             TEXT NOT NULL DEFAULT '',
  room             TEXT NOT NULL DEFAULT '',
  zone             TEXT NOT NULL DEFAULT '',
  status           TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','approved','blocked')),
  token_hash       BLOB,
  firmware_version TEXT NOT NULL DEFAULT '',
  config_json      TEXT NOT NULL DEFAULT '{}',
  first_seen       INTEGER,
  last_seen        INTEGER,
  created_at       INTEGER NOT NULL,
  updated_at       INTEGER NOT NULL
);

CREATE TABLE sessions (
  id         TEXT PRIMARY KEY,
  scenario   TEXT NOT NULL DEFAULT '',
  room       TEXT NOT NULL DEFAULT '',
  state      TEXT NOT NULL DEFAULT 'created' CHECK (state IN ('created','running','stopped')),
  started_at INTEGER,
  ended_at   INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE TABLE session_devices (
  session_id TEXT NOT NULL REFERENCES sessions(id),
  device_id  TEXT NOT NULL REFERENCES devices(id),
  PRIMARY KEY (session_id, device_id)
);

CREATE TABLE events (
  event_id      BLOB PRIMARY KEY,
  device_id     TEXT NOT NULL REFERENCES devices(id),
  seq           INTEGER NOT NULL,
  kind          TEXT NOT NULL,
  controller_id TEXT,
  session_id    TEXT REFERENCES sessions(id),
  ts_device     INTEGER NOT NULL,
  ts_server     INTEGER NOT NULL,
  payload       BLOB NOT NULL,
  UNIQUE (device_id, seq)
);

CREATE INDEX events_session_controller ON events (session_id, controller_id);
CREATE INDEX events_device_ts ON events (device_id, ts_server);
```

`payload` is the CBOR encoded `d` map from the protocol, stored as received. `controller_id` is extracted at insert time when present, so rankings do not need to decode payloads.

## 4. Tasks

### Task 1: dependency

`go get modernc.org/sqlite@latest`. Record the resolved version in D-009. Commit: `build(deps): add modernc.org/sqlite`.

### Task 2: `internal/store`, open and migrate

- `store.Open(ctx, dataDir) (*Store, error)`: creates `dataDir` if missing, opens `dataDir/theserver.db`, applies the PRAGMAs from D-011 on every connection (use a DSN with the pragmas or `db.SetConnMaxLifetime` plus a connect hook; verify with `PRAGMA journal_mode` in a test), runs migrations.
- Migrations in `internal/store/migrations/0001_init.sql`, embedded via `embed.FS`, applied in ascending order, each in its own transaction, version recorded in `schema_migrations`. Re-running is a no-op.
- Tests: fresh open creates all tables; second open applies nothing; `journal_mode` is `wal`; `foreign_keys` is on.

Commit: `feat(store): sqlite open with WAL and embedded migrations`.

### Task 3: devices

- `UpsertDevice(ctx, Device)`, `GetDevice(ctx, id)`, `ListDevices(ctx)`, `TouchLastSeen(ctx, id, ts)`, `SetStatus(ctx, id, status)`.
- `HashToken(token string) []byte` (SHA-256) and `VerifyToken(ctx, id, token) (bool, error)` with constant time comparison.
- Tests for each, including that an unknown status is rejected by the CHECK constraint.

Commit: `feat(store): device registry`.

### Task 4: the journal

- `AppendEvents(ctx, deviceID string, events []Event) (AppendResult, error)` in one transaction, `INSERT OR IGNORE` on `event_id`; a conflict on `(device_id, seq)` with a different `event_id` is an error `ErrSeqConflict`, not ignored. `AppendResult` carries `Stored`, `Duplicates`, and `AckSeq`, the highest seq such that all seqs 1..AckSeq exist for that device.
- `LastSeq(ctx, deviceID) (uint64, error)`: highest contiguous seq, 0 if none.
- `ListEvents(ctx, Filter)`: by device, session, kind, controller, time range, with limit and offset.
- `ts_server` is set by the store from an injectable clock, so tests are deterministic.
- Tests: append then re-append the same batch stores nothing new and returns the same `AckSeq`; a gap (seqs 1,2,4) yields `AckSeq` 2; filling the gap later raises it to 4; a seq reused with a different event id returns `ErrSeqConflict`; 10,000 events append in one transaction well under a second on the M150 (report the measured time, do not assert on it).

Commit: `feat(store): idempotent event journal with contiguous ack`.

- New flag `--db-info`: prints the database path, schema version, journal mode, and row counts for each table, then exits.
