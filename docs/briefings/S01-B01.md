# Briefing S01-B01: repository foundation for theserver

Track: theserver, Season S01. Repo: `https://github.com/cyb3rgun/theserver` (exists online, empty). Local: `C:\Projects\CYB3RGUN\THESERVER` (folder exists). Implementer: CC. Architect: Mausi.

Season S01 goal in one sentence: theserver runs as one binary on the M150, accepts events from a simulated target over the device link, journals them in SQLite, replays correctly after a dropped connection, and shows a ranking through the API and a first admin page.

This briefing delivers the foundation only. No device link, no database, no admin page yet.

## 1. Decisions taken in this briefing, with reasons

- **Go 1.26, latest patch.** Proven line. Go 1.27.0 shipped in August 2026 and is not yet the pinned toolchain; the upgrade is a recorded decision in a later pass, not a side effect.
- **Standard library first.** `net/http` for HTTP, `log/slog` for logging, `flag` for the command line. No web framework.
- **TOML configuration** with `github.com/BurntSushi/toml`. Comments in the file, human editable, machine writable later by the admin UI. Precedence: command line flags over environment variables over the file over built in defaults.
- **Layout by responsibility.** `cmd/theserver` is the only `main`. Everything else lives under `internal/` so nothing leaks as a public Go API by accident.
- **Docs trio** in `docs/`: `concept.md` (grows only), `decisions.md` (numbered, newest first), `seasons.md` (S track table). Plus `docs/briefings/` for briefings and `docs/handovers/` for handovers.
- **No licence file yet.** The licence for theserver is an open decision (concept, section 10). Do not add a LICENSE file and do not claim a licence in the README.

## 2. Hard constraints, valid for this and every later pass

1. No em dashes anywhere in the repo. Use `tools/check_dashes.py` (Python, not grep, for Windows) before every commit.
2. No invented versions. Every dependency is added with `go get <module>@latest` and the resolved version is written into `docs/decisions.md`. If a version cannot be resolved, stop and report; never type a version from memory.
3. No `go` directive in `go.mod` newer than the installed toolchain. Read `go version` first and record it.
4. Conventional Commits, one module per commit, English messages: `type(scope): description`.
5. Code, comments and documentation in English.
6. Nothing outside `C:\Projects\CYB3RGUN\THESERVER` is created or modified.
7. No git push in this pass.

### Task 3: Go module and skeleton

```
go mod init github.com/cyb3rgun/theserver
```

Folder layout:

```
cmd/theserver/main.go
internal/config/config.go
internal/config/config_test.go
internal/version/version.go
docs/
tools/check_dashes.py
README.md
```

`internal/version`: variables `Version`, `Commit`, `BuildDate`, set via `-ldflags "-X ..."`, defaulting to `dev`.

`internal/config`: a `Config` struct with, for now, these fields and defaults: `Server.ListenAddr` (`:8443`), `Server.DataDir` (`./data`), `Log.Level` (`info`), `Log.Format` (`text` or `json`). Loader order: defaults, then TOML file if present, then environment variables prefixed `THESERVER_` (for example `THESERVER_SERVER_LISTENADDR`), then flags. A function `WriteDefault(path)` writes a TOML file in which every setting appears with its default and a one line comment. Table driven tests for precedence.

`cmd/theserver/main.go`: flags `--config`, `--data-dir`, `--listen`, `--log-level`, `--version`, `--write-default-config <path>`. `--version` prints version, commit, build date and the Go version and exits 0. Otherwise: load config, set up `slog`, log "theserver starting" with the effective configuration, start a `net/http` server with a single route `GET /healthz` returning `200` and `{"status":"ok","version":"..."}`, and shut down cleanly on Ctrl+C with a 5 second grace period.

Commit split: `build(go): initialize module`, `feat(config): layered configuration with defaults, file, env and flags`, `feat(server): entry point with health endpoint and graceful shutdown`.
