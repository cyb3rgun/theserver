# Briefing S01-B04: rankings, API v1 and the first admin page

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, `main` at `5f70176`. Implementer: CC. Architect: Mausi.

This pass completes the Season S01 goal: rankings computed from the journal, served through the API, shown on a first admin page, together with the device administration the link now requires (approve, block, reset, new token). After this pass the founder runs the full chain on the M150: simulated targets, server, admin page.

## 1. Decisions taken in this briefing, with reasons

- **Rankings are computed, never stored.** A ranking is a query over `events` (kind `hit`, `pts` from the payload, grouped by `controller_id`), scoped to a session or to everything. No score table, no cache in S01. D-023.
- **`pts` is read from the CBOR payload by a dedicated `internal/scoring` package**, the only place outside the link that decodes payloads. The store stays payload agnostic. D-024.
- **Admin API tokens for S01.** `theserver admin token add --name <n>` prints a token once and stores its SHA-256 hash in a new `admin_tokens` table; every `/api/v1` request carries `Authorization: Bearer <token>`. Passkeys and roles are Season S02, the table is designed so that a passkey credential can sit beside a token later. D-025.
- **Device reset is an epoch, not a deletion.** `devices.seq_epoch` (default 1) is added; the events unique index becomes `(device_id, seq_epoch, seq)`; `LastSeq` and the handshake use the current epoch. `device reset` increments the epoch, so a device that lost its counter starts at 1 again and the old journal stays intact. Migration 0003. D-026.
- **Admin page with `html/template` plus HTMX**, served by the binary, no build step. HTMX is vendored as one minified file downloaded from its official release, version and SHA-256 recorded in D-027; the file is embedded, never loaded from a CDN. The page carries a plain base stylesheet for readability only; the visual design is the founder's and comes in a later pass. Nothing in the page exists without a working API call behind it. D-027.
- **OpenAPI written by hand**, `docs/openapi.yaml`, served at `/api/v1/openapi.yaml`, with a test that every registered route appears in it. D-028.

## 3. Tasks

### Task 1: scoring

`internal/scoring`: `Ranking(ctx, store, Scope) ([]Entry, error)` where `Scope` is `{SessionID string}` (empty means all sessions) and `Entry` is `{ControllerID, Hits, Misses, Points, LastHit}`. Points are the sum of `pts` from `hit` events; misses count `miss` events. A helper `PointsOf(payload []byte) (int, bool)` decodes only what it needs. Sorted by points descending, then hits, then controller id. Tests with a seeded store: two controllers, two sessions, one replayed duplicate that must not count twice, one event without `pts`.

Commit: `feat(scoring): rankings from the journal`.

### Task 2: epoch and admin tokens in the store

Migration 0003: `devices.seq_epoch INTEGER NOT NULL DEFAULT 1`, events unique index rebuilt as `(device_id, seq_epoch, seq)`, `events.seq_epoch INTEGER NOT NULL DEFAULT 1`, table `admin_tokens (id TEXT PRIMARY KEY, name TEXT NOT NULL, token_hash BLOB NOT NULL UNIQUE, created_at INTEGER NOT NULL, last_used INTEGER)`. Store functions: `ResetDevice(ctx, id)` (epoch plus one), `AppendEvents` and `LastSeq` epoch aware, `AddAdminToken`, `VerifyAdminToken` (constant time), `ListAdminTokens`, `RevokeAdminToken`. The link handshake reads the epoch and rejects a `hello` whose `last` exceeds the stored contiguous seq for the current epoch as before. Tests: reset then hello with `last=0` is accepted; old events remain queryable; token verify and revoke.

Commit: `feat(store): sequence epochs for device reset and admin tokens`.

### Task 3: API v1

`internal/httpapi`, all under `/api/v1`, JSON, bearer auth via `VerifyAdminToken`, 401 without it, 403 for a revoked token:

- `GET /devices`, `GET /devices/{id}`, `POST /devices/{id}/approve`, `POST /devices/{id}/block`, `POST /devices/{id}/reset`, `POST /devices/{id}/token` (returns a new device token once, replaces the old hash, closes a live connection)
- `GET /sessions`, `POST /sessions`, `POST /sessions/{id}/start`, `POST /sessions/{id}/stop`, `POST /sessions/{id}/devices` (body `{device_id}`)
- `GET /rankings?session=<id>` (empty means all)
- `GET /events?device=&session=&kind=&controller=&from=&to=&limit=&offset=`
- `GET /online` (from the link registry)
- `GET /openapi.yaml` (no auth)

Errors as `{"error":{"code":"...","message":"..."}}`. Tests with `httptest` for every route, including 401 and 403, and one end to end: simulated device connects, sends hits, `GET /rankings` shows them.

Commit: `feat(api): v1 endpoints for devices, sessions, rankings and events`.

### Task 4: admin page

`internal/admin`, mounted at `/admin`:

- `/admin/login`: paste an admin token once; on success a signed, HttpOnly, Secure cookie for 12 hours; logout clears it.
- `/admin/devices`: table with status, class, room, online, last seen, current epoch; buttons approve, block, reset, new token (token shown once in a modal), all through the API from Task 3.
- `/admin/sessions`: create, start, stop, assign devices.
- `/admin/ranking`: the ranking for a chosen session or all, refreshed by HTMX every 2 seconds.
- `/admin/settings`: the effective configuration, read only in S01, every setting with its source (default, file, env, flag).
- `/admin` redirects to devices.

Templates embedded, HTMX embedded, one base stylesheet with system fonts, readable tables and clear buttons, nothing decorative. Tests: login required on every page; the ranking fragment renders seeded data.

Commit: `feat(admin): first admin pages over the api`.
