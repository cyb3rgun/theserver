# Briefing S01-B10: the device journal on SQLite

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, `main` at the B09 handover or later. Implementer: CC. Architect: Mausi.

theclient's B01 found that `pkg/journal` (extracted from `simtarget` in B09) is a single CBOR file rewritten in full on every append and every ack, without fsync. For a simulator that was acceptable; for a target on an SD card that must keep hits across power loss it is not. `docs/concept.md` of theclient says SQLite; this pass makes `pkg/journal` say the same.

## 1. Decisions

- **`pkg/journal` stores in SQLite**, one file `journal.db` in the given directory, WAL mode, `synchronous=NORMAL`, `foreign_keys` on, via `modernc.org/sqlite` (already a dependency). Schema: `meta(key, value)` for device id, epoch and last acked seq; `events(seq INTEGER PRIMARY KEY, epoch, event_id BLOB, kind, ts_device, payload BLOB)`; append is one insert in a transaction; ack deletes rows up to the acked seq. D-052.
- **The public API of `pkg/journal` does not change.** Open, Append, Unacked, Ack, Epoch handling, Close keep their signatures; a migration path reads an existing `journal.cbor`, imports it, renames it to `.imported`. D-053.
- **Durability is tested, not assumed.** A test appends, kills the process image by closing without checkpoint, reopens, and finds every appended event; a crash test with a copied WAL file. D-054.
- **Tag `v0.2.0`** after this pass. D-055.
