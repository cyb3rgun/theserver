# Briefing S01-B11: the session tells the device what it plays

Track: theserver, Season S01. Repo `github.com/cyb3rgun/theserver`, `main` at the B10 handover or later. Implementer: CC. Architect: Mausi.

theclient's B02 found a hole: theserver never tells a device which scenario version its session plays. The device guessed from the last announcement. This pass closes the hole in the protocol, the link and the API, and tags `v0.3.0`.

## 1. Decisions

- **`welcome` carries the running session's scenario** as `scn {id, ver}` next to `ses`, or null when no session runs or none is assigned. D-056.
- **`session_start` carries `{ses, scn: {id, ver}}`**, and theserver sends it to every device of the session when the session starts, including devices that connect later while it runs (they get it right after `welcome`). `session_stop {ses}` as before. Section 8 of `docs/protocol.md` is appended; sections 1 to 7 unchanged. D-057.
- **A session cannot start without a published scenario assigned.** The API and the admin page refuse with a translated error. D-058.
- **A device that does not hold the version gets `content_available` first, then `session_start` after it reports `installed`**, with a timeout of `Link.InstallTimeoutS` (default 120) after which the admin page shows the device as "not ready" for that session. D-059.
- **Tag `v0.3.0`.** D-060.

## 2. Tasks

1. `feat(link)`: `scn` in welcome, `session_start` with scenario on start and on late connect, ordering after install per D-059; tests with the simulator: late connect, missing content, install then start.
2. `feat(api)`: start refuses without an assigned published scenario; session detail shows per device ready or not ready with reason; admin page follows, both languages; OpenAPI.
3. `feat(simtarget)`: answers `session_start` by logging the scenario it would play, so the end to end test can assert it.
4. `docs`: protocol section 8, D-056 to D-060, README, seasons, briefing; handover; push; tag `v0.3.0` pushed.

## 3. Acceptance

A device connecting after the session started receives `session_start` with the right scenario; a device without the content receives the announcement first and the start after `installed`; start without scenario is refused in API and admin; the tag exists.

`git log --oneline origin/main`, the tag, the end to end log lines for the three cases.
